\begin{abstract}
Ce document présente, selon une structure IMRaD, la conception fonctionnelle du pipeline R
\texttt{Inventaires\_completude\_representativite.R} (v1.4), dédié à l'analyse de complétude et
de représentativité d'inventaires fongiques par site. Les méthodes décrivent les exigences
d'entrée, la configuration centralisée, la validation CSV et les indicateurs calculés
(TEE, indice de représentativité, complétude). Les résultats formalisent l'organisation
thématique des sorties, les livrables globaux et par site, le système de journalisation ainsi
que les améliorations successives du script. La discussion précise l'interprétation des
indicateurs, les limites opérationnelles et les points de dépannage courants.
\end{abstract}

\section{Introduction}

\subsection{À propos}
Ce document formalise les exigences fonctionnelles du script :

\begin{center}
  \texttt{scripts/Inventaires\_completude\_representativite.R}
\end{center}

(v1.4), destiné à l'analyse de complétude et de représentativité d'inventaires fongiques.

\subsection{Objectifs du pipeline}

Le pipeline réalise, pour chaque site :

\begin{enumerate}[label=\arabic*.]
  \item la courbe temps-espèces,
  \item les ajustements linéaire/hyperbolique (si conditions remplies),
  \item l'estimation d'asymptote,
  \item le calcul de \texttt{TEE} et de $Ir = 1 - TEE$,
  \item les fréquences d'occurrence par espèce,
  \item l'occupation spatiale (si \texttt{placette}),
  \item la CA/AFC (si \texttt{vegan}),
  \item les métriques de pertinence scientifique,
  \item le manifeste final de production.
\end{enumerate}

\subsection{Dépendances et pré-requis}

Packages requis : \texttt{dplyr}, \texttt{tidyr}, \texttt{ggplot2}, \texttt{purrr}, \texttt{readr},
\texttt{stringr}, \texttt{forcats}, \texttt{tibble}, \texttt{scales}, \texttt{gridExtra}.\\
Packages optionnels : \texttt{minpack.lm} (modèle hyperbolique), \texttt{vegan} (CA/AFC).

\section{Méthodes}

\subsection{Structure attendue des données d'entrée}

\subsubsection{Fichier principal}
\texttt{data/observations.csv} (ou \texttt{.txt}/\texttt{.tsv})

\subsubsection{Colonnes}
\begin{itemize}
  \item Obligatoires : \texttt{site}, \texttt{date}, \texttt{visite\_id}, \texttt{espece}
  \item Optionnelle : \texttt{placette}
\end{itemize}

\subsubsection{Règles fonctionnelles}
\begin{itemize}
  \item Parsing date via \texttt{INVENTAIRES\_DATE\_FORMAT} (défaut : \texttt{\%Y-\%m-\%d}).
  \item Déduplication sur \texttt{(site, placette, date, visite\_id, espece)}.
  \item Visite distincte : \texttt{date + visite\_id} (et \texttt{site} en multi-sites).
\end{itemize}

\subsection{Configuration centralisée}
\label{sec:config}

Tous les paramètres du pipeline sont définis dans la fonction \texttt{get\_embedded\_config()} et
affichés dans l'en-tête du script au démarrage. La configuration supporte les surcharges via
variables d'environnement \texttt{INVENTAIRES\_*} :

\begin{itemize}
  \item \texttt{INVENTAIRES\_INPUT\_FILE} : chemin du fichier source
  \item \texttt{INVENTAIRES\_OUTPUT\_DIR} : répertoire de sortie
  \item \texttt{INVENTAIRES\_DATE\_FORMAT} : format des dates
  \item \texttt{INVENTAIRES\_CSV\_STRICT} : mode strict (booléen)
  \item \texttt{INVENTAIRES\_CSV\_ALLOW\_EXTRA\_COLS} : tolérance colonnes supplémentaires
  \item \texttt{INVENTAIRES\_FREQ\_BREAKS} : séquence des intervalles de fréquence
  \item \texttt{INVENTAIRES\_FREQ\_LABELS} : étiquettes des intervalles
  \item \texttt{INVENTAIRES\_MAKE\_CA} : activer CA/AFC (booléen)
  \item \texttt{INVENTAIRES\_MIN\_VISITS\_FOR\_MODEL} : seuil de modélisation
  \item \texttt{INVENTAIRES\_WIDTH}, \texttt{INVENTAIRES\_HEIGHT}, \texttt{INVENTAIRES\_DPI} : paramètres graphiques
\end{itemize}

\begin{infobox}[Aucune modification du code source]
Les paramètres peuvent être ajustés par variable d'environnement, sans toucher au script.
\end{infobox}

\subsection{Validation CSV}

Le contrôle de conformité est exécuté avant traitement.
\begin{itemize}
  \item \texttt{results/ICR/ICR\_00\_csv\_conformite\_report.csv} (toujours)
  \item \texttt{results/ICR/ICR\_00\_csv\_conformite\_problems.csv} (si anomalies)
\end{itemize}

\begin{warnbox}[Mode strict]
En mode strict (\texttt{INVENTAIRES\_CSV\_STRICT=TRUE}), la non-conformité est bloquante.
\end{warnbox}

\subsection{Indicateurs calculés}

\subsubsection{TEE}
Proportion d'espèces observées une seule fois.

\subsubsection{Indice de représentativité}
\begin{formulebox}[Formule]
\[
Ir = 1 - TEE
\]
\end{formulebox}
Repères : \texttt{Ir < 0.60} (faible), \texttt{0.60 <= Ir < 0.80} (moyenne), \texttt{Ir >= 0.80} (bonne).

\subsubsection{Complétude}
\begin{formulebox}[Formule]
\[
\text{Complétude} = \frac{S_{obs}}{S_{asymptote}}
\]
\end{formulebox}
Repères : \texttt{< 0.70} (insuffisante), \texttt{0.70--0.90} (intermédiaire), \texttt{>= 0.90} (avancée).

\subsection{Variables d'environnement supportées}
\begin{itemize}
  \item \texttt{INVENTAIRES\_INPUT\_FILE}
  \item \texttt{INVENTAIRES\_OUTPUT\_DIR}
  \item \texttt{INVENTAIRES\_DATE\_FORMAT}
  \item \texttt{INVENTAIRES\_CSV\_STRICT}
  \item \texttt{INVENTAIRES\_CSV\_ALLOW\_EXTRA\_COLS}
  \item \texttt{INVENTAIRES\_AUTO\_RUN}
\end{itemize}

\subsection{Modes d'exécution}
Le script peut être exécuté en mode standard (recommandé) ou avec des flags internes :
\begin{itemize}
  \item \texttt{DEBUG\_MODE = TRUE} : verbosité accrue et affichage détaillé des avertissements.
  \item \texttt{BENCHMARK\_MODE = TRUE} : mesure des temps sur les calculs principaux.
  \item \texttt{CLEAN\_ENVIRONMENT = TRUE} : nettoyage de l'environnement avant exécution (usage expert).
\end{itemize}
Le comportement d'auto-lancement est piloté par \texttt{INVENTAIRES\_AUTO\_RUN} (défaut : \texttt{TRUE}).

\section{Résultats}

\subsection{Organisation thématique des sorties}
Les résultats sont organisés selon une hiérarchie thématique sous \texttt{results/ICR/} :

\begin{itemize}
  \item \texttt{00\_data\_quality/} : rapports d'audit CSV et conformité
  \item \texttt{01\_richesse/}, \texttt{02\_completude\_repr/}, \texttt{03\_frequences/} : analyses par site (réservées)
  \item \texttt{04\_spatial/}, \texttt{05\_temporal/} : analyses spéciales (réservées)
  \item \texttt{06\_metrics/} : métriques scientifiques globales
  \item \texttt{comparisons/} : visualisations comparatives multi-sites
  \item \texttt{sites/<site\_name>/} : tous les fichiers par site (organisés en un seul répertoire)
\end{itemize}

\subsection{Sorties globales (\texttt{results/ICR/})}

  \item \texttt{ICR\_06\_CA\_placettes\_especes.png} (si vegan et placette)

\subsection{Système de logging}

Chaque exécution du script génère un fichier log horodaté dans le répertoire \texttt{logs/} du projet :

\begin{itemize}
  \item \textbf{Format du nom} : \texttt{ICR\_YYYYMMDD\_HHMM.log}
  \item \textbf{Format des entrées} : \texttt{[YYYY-MM-DD HH:MM:SS] [LEVEL] message}
  \item \textbf{Niveaux} : \texttt{INFO}, \texttt{DEBUG}, \texttt{WARN}
\end{itemize}

Les logs enregistrent :
\begin{enumerate}
  \item l'en-tête du script (nom, version, timestamp, répertoire de travail, version R) ;
  \item chaque étape du pipeline (résolution fichier, audit CSV, analyses par site) ;
  \item les paramètres de configuration actifs au démarrage ;
  \item le manifeste final des livrables avec statuts (\texttt{OK}, \texttt{MANQUANT}, \texttt{OPTIONNEL\_NON\_GENERE}).
\end{enumerate}

Les avertissements sont également affichés en console et dans les logs en niveau \texttt{WARN}.

\subsection{Améliorations du script (v1.4)}

\subsubsection{Phase 1 : Fiabilisation}
Gestion robuste des formats de fichiers hétérogènes, déduplication intelligente des observations, traitement des dates flexibles, gestion des erreurs CSV granulaire.

\subsubsection{Phase 2 : Performance}
Optimisation du modèle hyperbolique via \texttt{minpack.lm::nlsLM}, calculs vectorisés par site, graphiques pré-calculés en mémoire avant export PNG.

\subsubsection{Phase 3 : Graphiques et visualisations}
Cartes de chaleur multi-sites, tableaux de bord par site (7 graphiques), comparaisons visuelles de complétude, analyses de CA/AFC si \texttt{vegan} disponible.

\subsubsection{Phase 4 : Industrialisation}
\begin{enumerate}
  \item \textbf{Configuration centralisée} : fonction \texttt{get\_embedded\_config()} avec 14+ paramètres, surchargeable via variables d'environnement
  \item \textbf{Logging systématisé} : fichiers logs horodatés avec métadonnées d'exécution, manifeste final des livrables
  \item \textbf{Organisation thématique} : hiérarchie logique /sites/, /comparisons/, répertoires réservés pour extensions futures
  \item \textbf{Métriques scientifiques} : pertinence des espèces, scores de complétude détaillés, dashboards analytiques
\end{enumerate}

\section{Discussion}

\subsection{Journalisation fonctionnelle}
La sortie est journalisée en console (niveaux info/debug/warning), puis un manifeste final indique l'état des livrables :
\texttt{OK}, \texttt{MANQUANT}, \texttt{OPTIONNEL\_NON\_GENERE}.

Le script applique enfin une politique stricte de nettoyage du fichier parasite \texttt{Rplots.pdf} lorsqu'il est généré pendant l'exécution.

\subsection{Limites et perspectives}
La disponibilité de certaines sorties dépend de la richesse du jeu de données fourni : sans la
colonne \texttt{placette}, l'analyse spatiale n'est pas produite ; sans le package
\texttt{minpack.lm}, l'asymptote hyperbolique n'est pas estimée ; sans le package
\texttt{vegan}, la CA/AFC n'est pas générée ; en deçà du seuil
\texttt{INVENTAIRES\_MIN\_VISITS\_FOR\_MODEL}, la modélisation est ignorée. En mode strict, un
CSV non conforme bloque le pipeline.

\subsection{Dépannage (FAQ)}
\begin{description}
  \item[Le script ne trouve pas le fichier d'entrée.]
    Vérifier qu'un fichier \texttt{.csv}, \texttt{.txt} ou \texttt{.tsv} est présent dans \texttt{data/}
    et que son nom correspond à \texttt{INVENTAIRES\_INPUT\_FILE}.

  \item[Colonnes manquantes à l'exécution.]
    Vérifier que les colonnes obligatoires \texttt{site}, \texttt{date}, \texttt{visite\_id},
    \texttt{espece} sont présentes avec les noms exacts attendus.

  \item[Le pipeline s'arrête en mode strict.]
    Consulter \texttt{results/ICR/ICR\_00\_csv\_conformite\_problems.csv} pour identifier les
    anomalies, ou désactiver temporairement \texttt{INVENTAIRES\_CSV\_STRICT}.

  \item[Pas d'occupation spatiale ni de CA/AFC.]
    Vérifier la présence de la colonne \texttt{placette} et, pour la CA/AFC, l'installation du
    package \texttt{vegan}.

  \item[Pas d'asymptote hyperbolique.]
    Vérifier l'installation du package \texttt{minpack.lm} et que le nombre de visites du site
    atteint \texttt{INVENTAIRES\_MIN\_VISITS\_FOR\_MODEL}.
\end{description}
